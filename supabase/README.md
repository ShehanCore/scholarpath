# Database

- `migrations/` — schema, row-level security and grants. Apply in filename order.
- `seed.sql` — content generated from `design/data/*.json` with the corrections in `design/BUILD_PLAN.md`. Safe to re-run. Regenerate with `npm run db:seed:generate`; don't edit by hand.
- `ranks/` — optional SQL generated by `npm run db:ranks` from a rankings CSV (see below).
- `tests/` — runs the migrations, seed and RLS tests against any local Postgres: `PGPORT=5432 supabase/tests/run.sh`.

## Set up a Supabase project

1. Create a project at supabase.com (region: Mumbai `ap-south-1` is closest to Sri Lanka).
2. SQL Editor → paste and run `migrations/20261026000000_initial_schema.sql`, then `seed.sql`.
   (Or with the Supabase CLI: `npx supabase link --project-ref <ref>` then `npx supabase db push` and run the seed.)
3. Project Settings → API Keys: copy the project URL and the **publishable** key into `.env.local` and into Vercel
   (see `.env.example`). The **secret** key goes only in Vercel's server-side environment variables, never in the browser or in chat.

Until step 3, the app reads the same content from `design/data`, so it builds and runs without a database.

## University ranks

Ranks live in `rankings` (one row per university per year: `rank_display` exactly as published, `rank_sort` for ordering). The seed loads the THE World University Rankings 2027 ranks recorded in `design/data/universities.json`. A university without a row shows "Rank band: to confirm".

- **Edit a rank:** `/admin/rankings` (see `.env.example` for the admin login and the secret key it needs).
- **Yearly update:** edit in the admin, or import a file you downloaded yourself: make a CSV with a header `rank,name` (copy both exactly as published), run `npm run db:ranks -- ranks.csv --year 2028`, then run the generated `ranks/ranks-2028.sql` in the SQL Editor. Only universities ScholarPath lists are imported. Check THE's terms before publishing more ranks; license the data from THE for a full list.
- Never fetch THE from the app, and never type ranks from memory.

## Sign-in (Supabase Auth)

1. Authentication → URL Configuration: set **Site URL** to your site (e.g. `https://scholarpath.lk`) and add
   `https://scholarpath.lk/auth/callback` and `http://localhost:3000/auth/callback` to **Redirect URLs**.
2. Authentication → Providers → Email: keep "Confirm email" on. Minimum password length 8.
3. Google: follow `docs/google-sign-in.md` (Google Cloud OAuth client, then enable the provider here).
   Until it's set up, "Continue with Google" shows "Google sign-in isn't available yet".
4. Emails: the default templates work (links go through `/auth/callback`). To use your own domain for auth
   emails, set up custom SMTP under Authentication → Emails.

Registration step 1 sends name, role, WhatsApp number (required) and opt-in, and terms consent as sign-up metadata; the
`handle_new_user` trigger copies them into `profiles` (malformed values are dropped). WhatsApp opt-in and
opt-out times are recorded by the `profiles_whatsapp_consent` trigger.

Signed-in students' saved scholarships, eligibility answers and checklists sync between the browser and
`saved`, `eligibility_answers`, `checklists` and `checklist_items` (see `src/components/account-sync.tsx`).
"Download my data" is `/account/export`; "Delete my account" removes the auth user, which cascades.
